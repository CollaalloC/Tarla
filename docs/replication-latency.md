# 双节点 S2 同步和任务回执延迟

2026 年 11 月 20 日，在同一台 Linux x86_64 主机上运行两个独立的 `tarlad` 进程，各用独立工作目录和 SQLite WAL 数据库。主管与执行机通过带配对凭据的 TCP 回环连接通信。基准使用 Rust debug 构建，机器报告的 CPU 为 AMD EPYC 7763。以下结果描述这次运行，真实网络 RTT、磁盘负载、代理或模型延迟会影响结果。

| 观测区间 | 次数 | p50 | p95 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| 主管 API 确认写入 → 执行机 API 可读该版本 | 30 | 22.21 ms | 46.26 ms | 48.17 ms |
| 主管写入请求开始 → 执行机 API 可读 | 30 | 30.48 ms | 56.23 ms | 172.98 ms |
| 执行机 API 确认提案已入队 → 同机读到主管定序后的版本 | 30 | 30.20 ms | 40.39 ms | 41.32 ms |
| 执行机提案请求开始 → 同机读到主管定序后的版本 | 30 | 36.74 ms | 47.83 ms | 48.81 ms |
| 执行机 S1 回执入队 → 主管归档该回执 | 8 | 19 ms | 46 ms | 46 ms |
| 执行机 S1 回执入队 → 主管归档助手汇报 | 8 | 33 ms | 67 ms | 67 ms |

此前仅靠约 900 ms 一次的同步轮询，同一脚本、相同采样参数测得“主管 API 确认 → 执行机 API 可读”为 p50 **442.42 ms**、p95 **866.48 ms**。当前版本在记忆事务提交后向每个已配对执行机发送经过鉴权的游标变更提示。一个执行机最多占用一个在途提示，短时连续修改会合并。执行机从自己的持久游标拉取并验证增量。如果提示丢失或反向路由不可达，周期性同步仍会补传。工作空间、主管身份及任期检查与其他节点 API 相同。

## 测量口径

- 每个方向先预热三次，再连续采集 30 次。每次提交之间使用固定种子 211 生成 0–700 ms 随机间隔，减少请求与轮询周期总是对齐的偏差。报告使用最近秩分位数。
- 观测端每隔至少 3 ms 使用执行机业务 API 检索，核对记忆标识和版本。结果包含读取请求和检查周期，反映客户端实际看到结果的时间。
- 停止主管进程后，一次本地记忆查询耗时 **4.90 ms**。执行机离线接受了下一版本的提案。随后重启主管，从启动命令到主管写入且执行机重新读到该版本，共 **946.22 ms**。这两项各测一次。
- 回执测试派发八个具有缺失环境事实前置条件的任务。真实执行机在预检中产生失败回执，主管按实际 S1 Outbox、去重和会话唤醒路径处理。时间戳由两个临时测试数据库中各自的插入触发器记录，使用同机墙钟，精度为 1 ms。最后一跳使用流式模型 API 的本地测试服务。这里的汇报时间不含外部大模型的推理延迟。

## 任务完成后，另一台执行节点多久能读到经验

阶段二的验收使用同一台 GitHub Linux 主机上的三个独立守护进程和三个 SQLite 数据库。执行节点 A 上的五个真实 Herdr 作业分别输出不同的观察。主管核对回执后，节点 B 将对应经验写入本地数据库。测试使用同一个单调时钟每 2 ms 查询两端已提交的数据，以两次提交的观测区间中点估算延迟。

从 A 的成功回执落盘到 B 的经验落盘，五次分别为 **51.0、42.8、50.6、53.3、55.4 ms**，中位数 **51.0 ms**。另一次测试阻断回执确认，独立的手工记忆仍能提交。放行回执后，A 在 **15 ms** 后发出自动提案。在三个独立 Linux 网络命名空间中，恢复镜像接口后 **312 ms** 即可检索该经验，停止主管后同一查询仍然成功。部署到不同地区时需要按实际链路重新测量。[原始验收日志](https://github.com/CollaalloC/Tarla/actions/runs/44656268116/job/136023136980)

## 复现

从仓库根目录运行以下命令。脚本会创建并清理测试节点，输出 JSON，验收只断言正确性，无固定网络时延门槛。

```bash
cargo build --locked -p tarlad -p tarla-cli
python3 tests/replication_latency.py --warmup 3 --samples 30 --jitter-ms 700 --read-interval-ms 3 --seed 211 --receipt-samples 8
```

加入 `--pull-only` 可将主管的反向通知地址指向一个不接受连接的本地端口，保留执行机主动拉取路径。脚本验证已落盘数据的离线检索、离线提案恢复，并检查工作空间客户端凭据、错误主管任期以及非主管节点均不能触发复制提示。

如需对真实成功作业测量，将 `TARLA_TEST_HC` 设为已校验的 `herdr-core` 可执行文件，并加入 `--successful-receipts`。该模式从执行机作业写出完成标记一直测到主管助手汇报可读，需要支持私有 PTY 守护进程的原生运行环境。

设置同一环境变量后，运行 `python3 tests/stage2_distillation.py` 可复现五个真实作业的三节点测量，输出每个样本的观测区间及其中点。
