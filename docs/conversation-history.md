# 主管的会话归档与模型窗口

`messages` 保存按会话递增排序的原始消息。每轮只把当前使用的静态前缀、历史 DAG 摘要和最近消息发给模型。默认保留最近八轮原文。超过水位后，守护进程在回复落库后折叠较早的消息。新输入直接越过硬上限时，请求路径会先压缩。摘要的每个节点保存原文序号区间，中文决策和约束可从叶节点检索。

工作空间第一次为该会话调用模型时，SQLite 冻结当时的 SOUL 和 S2 快照，缓存实际发送的系统前缀。修改 SOUL 或 S2 后，新会话使用新内容，已有会话继续使用其冻结版本。旧版数据库仅保存了冻结记忆，升级后首次恢复该会话时会记录当时可用的 SOUL。升级前未存档的 SOUL 历史版本无法从旧数据库恢复。

若单条输入、多个受保护轮次或静态前缀本身超过窗口，模型接收 UTF-8 边界完整的首尾摘录以及归档句柄。多个句柄仍占满窗口时，较早的连续条目会共享一个范围句柄。原文完整保存在本机，可通过 `GET /v1/conversations/{id}/messages` 分页读取。模型可调用 `session_recall` 按关键词或 DAG 节点查找消息，传入 `seq_no`、`offset_bytes` 和 `max_bytes` 逐段读取；返回的 `next_offset_bytes` 指向下一段。`profile`、`model_memory` 分别读取冻结的角色设定和主管提示词使用的记忆，`frozen_memory` 读取含执行器观察的原始快照。可用 `receipts_only: true` 和 `after_seq` 分页读取指定 DAG 节点内的全部回执。每页最多 1,024 个 UTF-8 字节；每次调用都限定在当前会话。

预算采用 UTF-8 字节和协议开销的保守估算。主管窗口预留工具说明与回读空间；派单及回执按每 Token 4 个 UTF-8 字节折算序列化后（含转义）的完整 JSON 上限，默认分别为 1,800 Tokens（7,200 字节）和 500 Tokens（2,000 字节），回执优先为前两个完整产物引用预留空间。必填派单条件超出预算时返回错误。执行原始日志保留在 S0，可以用回执中的运行指针查询。

`python3 tests/stage1_history.py` 使用真实守护进程与确定性的本地 HTTP 模型端点，检查 156 轮中文对话、超长单条输入、逐条原文恢复、冻结前缀、模型工具回读、空闲压缩、实际派单与回执。先运行 `cargo build --locked -p tarlad -p tarla-cli` 构建二进制。
