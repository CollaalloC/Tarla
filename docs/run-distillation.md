# 从完成回执提取项目经验

执行节点完成成功任务时，将有界回执和待提取任务一起写入本地 SQLite。后台任务从回执中挑选一条可供同类任务复用的技术观察。原生驱动的最终答复、运行自己提交的结构化回执均可作为来源。对于只写终端的进程，执行机会在最终画面末尾最多 8 KiB、40 行内寻找候选。普通完成提示、失败、取消、密钥样式的文本及操作指令会被跳过。原始日志继续保存在执行机。

默认的确定性提取器识别中文和英文中的因果、依赖、兼容性等关系。可在执行节点工作空间的 `workspace.toml` 中配置本地 OpenAI 兼容服务，让模型从自然语言候选中选出值得保留的经验。例如：

```toml
[memory.distiller]
endpoint = "http://127.0.0.1:8080/v1/chat/completions"
model = "local-instruct"
```

本地接口必须使用显式回环 IP。请求仅包含筛选后的候选句，最多八句、每句最多 220 个 UTF-8 字节。模型可以返回 `{"index":0}` 选择第一句，或返回 `{"index":null}` 放弃提取。工具调用、越界索引、自行编写的结论都会被丢弃。连接失败时，已有的确定性观察可继续提交；其余符合条件的回执留在队列中重试。模型调用在独立后台任务中运行。

派单时，主管按派单的记忆作用域和任务目标计算经验条目的标识，并在同一事务中记录当时的记忆版本。执行结果无法指定写入哪条记忆。提案携带原运行标识、执行节点、基线版本和 HLC，经已有的 S2 提案队列送往主管。主管用已接受的成功回执再次核对候选原文、任务归属和冻结基线。相同运行重放只会产生一个提案。中途发生的人工修订留在当前版本，过期的提案进入冲突候选。目标文字变更会产生另一个条目标识。

执行机离线时会保存待提取回执及待发提案。提案获主管确认后按 `sync_seq` 复制到配对节点，其他设备可离线读取。下次派发同一项目作用域的任务时，若预取预算足够，该观察会随冻结快照送入新任务。每条自动提取的观察都注明执行机及运行标识，供用户根据原始记录复核。来源核对只能证明执行机报告过这句话，无法独立证明该观察在其他环境也成立。

主管分别冻结完整记忆快照和仅含用户条目的系统提示投影。执行机报告的经验保留运行来源，可通过工具检索、冻结快照分页回读或任务包提供给执行工位。主管的 SOUL 系统提示只附加经原始修订核验的用户条目。升级旧库时保留冻结原文，无法核实来源的内容留在数据层。

`tests/stage2_distillation.py` 使用三个独立守护进程、真实的私有 herdr-core、两个实际执行工位和一个本地 HTTP 测试端点。覆盖默认提取、模型选择、拒收模型编造的内容、同作用域复用、跨作用域隔离、离线重启、人工编辑期间的版本冲突及伪造提案。
